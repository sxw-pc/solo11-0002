# scan-lab 项目说明

> 版本：0.1.0
> 适用范围：本地、离线、仅用于自有或已获授权的靶场。
> 本文档描述的是**当前已经实现**的行为，不包含未来计划。

### 1.2 各文件职责

| 文件 | 职责 |
| --- | --- |
| `src/scan_lab/cli.py` | 唯一 CLI 入口，负责参数解析、日志初始化、异常到退出码的映射。console_scripts 名称是 `scan-lab`。 |
| `src/scan_lab/config.py` | 定义 `HttpSettings` / `CrawlSettings` / `ScanSettings` 三个 pydantic 模型；加载 `config/scan.yaml`；把 CLI 覆盖项合并进配置；`ensure_local_target` 拒绝非本机目标。 |

| `src/scan_lab/crawl.py` | `Form` / `Page` / `CrawlResult` 模型；`normalize_url`、`same_origin`、`query_params`、`set_query_param`、`extract_forms` 等工具函数；`Crawler` 执行同源 BFS。 |
| `src/scan_lab/plugin.py` | `Severity` / `Confidence` 字面量类型；`Finding` 模型；`Plugin` 抽象基类；全局注册表与 `register_plugin` / `available_plugins` / `get_plugin`。 |
| `src/scan_lab/plugins/*` | 具体检测逻辑。导入包即触发注册。 |
| `src/scan_lab/evidence.py` | 截取 marker 附近的响应片段、拼装请求摘要、生成 cURL 复现命令。 |
| `src/scan_lab/report.py` | `ScanMeta` / `ScanStats` / `Report` 模型；`dedupe_findings`；`write_report`；`print_summary`；默认报告路径。 |
| `src/scan_lab/scanner.py` | 扫描编排层：校验插件名、创建会话、调用爬虫、逐个插件匹配并探测、汇总统计、生成 `Report`。 |
| `target/app.py` | 故意有漏洞的 Flask 应用；所有路由都返回 HTML。 |
| `target/seed.py` | 建表与写入种子数据；提供 `init_db`、`ensure_seeded` 和 `python -m target.seed` 入口。 |
| `tests/conftest.py` | 用 `werkzeug.serving.make_server` 在随机端口启动靶场，用临时 sqlite 初始化种子数据；提供快速 HTTP 配置、客户端和"已关闭端口" fixture。 |

### 1.3 三条边界

1. **CLI 入口边界**：外部只通过 `scan-lab` 三个子命令与项目交互。任何退出码和用户可读错误都在 `cli.py` 统一收口。
2. **插件扩展点**：检测逻辑只存在于 `src/scan_lab/plugins/`。新增插件不改动爬虫、报告和 CLI，只需继承 `Plugin` 并注册。
3. **靶场与扫描器边界**：`target/` 只负责"提供可被探测的 HTTP 行为"，扫描器只通过 HTTP 访问它，不导入靶场内部函数、不共享数据库连接。测试时靶场由测试进程内的线程启动。

## 2. 功能说明（F1–F8）

### F1 靶场（`target/app.py`）

- **输入**：HTTP 请求。`GET /`、`GET /search?q=`、`GET /files?path=`、`GET /profile?id=`、`GET|POST /login`。
- **处理**：Flask 路由直接渲染 HTML；`/login` 使用字符串拼接构造 SQL；`/search` 把 `q` 原样写入页面；`/files` 直接拼接 `target/files/` 与 `path`；`/profile` 只按 id 查询、不校验归属。
- **输出**：HTML 页面；`/files` 和 `/profile` 找不到内容时返回 404 页面。
- **边界与失败行为**：仅绑定本机；数据库默认 `target/scan_lab.db`，首次启动自动建库；所有账号/口令均为虚构演示数据。

### F2 爬虫（`src/scan_lab/crawl.py`）

- **输入**：起始 URL、`CrawlSettings`（`max_depth` 默认 2、`max_urls` 默认 50、`skip_keywords` 默认 logout/delete/signout）。
- **处理**：
  1. 用 `normalize_url` 补全相对链接、去掉 fragment、把 query 按参数名排序、scheme/netloc 转小写；
  2. 起始页立即访问，失败直接抛出 `FetchError`；
  3. 从 `a[href]` 收集链接，从 `form[action][method]` 与 `input/select/textarea[name]` 收集表单；
  4. 只保留与起点同源的链接；路径命中 `skip_keywords` 的链接跳过；
  5. 已入队的规范化 URL 不再重复入队；达到 `max_depth` 后不再展开；页面数达到 `max_urls` 后停止。
- **输出**：`CrawlResult(pages=[Page...], skipped=[url...])`。`Page` 含 `url`、`method="GET"`、`params`（query 参数名）与 `forms`（action/method/inputs）。
- **边界与失败行为**：
  - 起始页连接拒绝/超时 → `FetchError` 向上传播，CLI 退出码 2；
  - 起始页响应为空 → `ParseError` 向上传播，CLI 退出码 2；
  - 后续页面请求失败或解析失败 → 记入 `skipped`，继续爬取；
  - 非 http(s) 链接（mailto、javascript、data 等）直接丢弃；
  - 不访问外域，即使页面里出现绝对外链。

### F3 插件框架（`src/scan_lab/plugin.py`）

- **输入**：`Page`（由爬虫产出）、插件名列表、共享的 `HttpClient`。
- **处理**：
  - `Plugin` 抽象类声明 `name`、`severity`、`confidence`、`description`；
  - `match(page)` 做轻量判断；`run(page)` 执行探测；
  - `@register_plugin` 把插件类写入全局注册表；同名重复注册直接抛 `PluginError`；
  - `available_plugins()` 首次调用时导入 `scan_lab.plugins` 包，触发内置插件注册；
  - `get_plugin(name, client)` 按名字实例化，未知名字抛 `PluginError`。
- **输出**：已实例化的插件对象；每个插件的 `run` 返回 `list[Finding]`。
- **边界与失败行为**：
  - CLI 传入未知插件名时，`scanner.run_scan` 在发出任何 HTTP 请求前抛出 `PluginError`，CLI 打印原因并以退出码 2 结束；
  - 单个插件在单页上的请求失败或插件异常计入 `skipped`，不中断其他插件；
  - 插件之间不共享可变状态，只共享本次扫描的 HTTP 会话。

### F4 两个插件

#### `xss_reflect`

- **输入**：带 GET 查询参数的 `Page`。
- **处理**：对每个参数生成唯一标记 `<sl{8位十六进制}>`（例如 `<sl1a2b3c4d>`），用标准 URL 编码写入该参数并发起 GET；检查响应正文中是否出现**原始未转义**标记。若页面做了 HTML 转义，正文只会出现 `&lt;sl...&gt;`，不会命中。
- **输出**：每个命中的参数一条 `Finding`；`severity=high`，`confidence=high`；证据包含实际请求 URL、HTTP 状态码和标记附近的响应片段；`repro_curl` 可直接复现。
- **边界与失败行为**：页面没有查询参数时 `match` 返回 False；响应中没有原始标记时返回空列表，不产生 finding；请求失败抛 `FetchError`，由扫描器记入 `skipped`。`/files?path=...` 注入标记后目标返回静态 404，正文不含标记，因此不会误报。

#### `path_traversal`

- **输入**：参数名包含 `path`、`file` 或 `filename` 的 GET 页面。
- **处理**：依次尝试 4 个 payload：`../../etc/passwd`、`..%2f..%2fetc%2fpasswd`、`....//....//etc/passwd`、`../etc/passwd`。其中编码变体使用"原样拼接"写入 query，避免被再次编码。若响应正文包含 `root:`，判定命中。
- **输出**：每个参数最多一条 `Finding`（命中首个 payload 后停止该参数）；`severity=high`，`confidence=high`；证据保留实际请求 URL、状态码与包含 `root:` 的响应片段。
- **边界与失败行为**：参数名不在文件读取集合内时 `match` 返回 False；4 个 payload 都没有 `root:` 时返回空列表；网络失败计入 `skipped`。

### F5 报告（`src/scan_lab/report.py`）

- **输入**：去重前的 `list[Finding]`、目标地址、起止时间、配置快照、请求/跳过统计。
- **处理**：按 `(plugin, url, parameter)` 去重并保留第一次出现的记录；组装 `Report`；序列化为 JSON；终端打印统计和每条 finding 一行摘要。
- **输出**：JSON 文件（默认 `reports/scan-{YYYYmmdd-HHMMSS}.json`，可用 `--out` 覆盖）；终端摘要包含目标、时间、请求数、跳过数、耗时、各插件命中数；每条 finding 一行：插件 / 严重级 / URL / 参数 / payload。
- **边界与失败行为**：输出目录不存在时自动创建；目录不可写等 `OSError` 由 CLI 捕获，打印"报告写入失败"并以退出码 1 结束；去重只影响展示，不改变 `stats.requests`。

### F6 错误处理（`src/scan_lab/errors.py`）

- **输入**：网络异常、解析失败、插件失败、配置错误。
- **处理**：
  - `FetchError`：超时、连接拒绝、URL 非法等；
  - `ParseError`：起始 URL 非法、响应为空、HTML 解析失败；
  - `PluginError`：插件注册/查找/执行失败；
  - `ConfigError`：配置或目标校验失败；
  - 代码中没有裸 `except Exception`，只捕获具体异常类型。
- **输出**：可读错误信息与退出码。
- **边界与失败行为**：
  - 单个非起始页面超时/连接拒绝 → 记入 `skipped` 继续；
  - 插件单次探测失败 → 记入 `skipped` 继续；
  - 目标首页不可达 → 打印 `目标不可达: <原因>（<url>）`，退出码 2，不打印堆栈；
  - 报告写入失败 → 退出码 1。

### F7 CLI（`src/scan_lab/cli.py`）

- **输入**：命令行参数。
- **处理**：Typer 解析参数 → 加载配置 → 合并 CLI 覆盖 → 校验目标为本地 → 解析插件名 → 扫描 → 写报告 → 打印摘要。
- **输出**：三个子命令。

```text
scan-lab serve-target --port 5001
scan-lab scan --target http://127.0.0.1:5001 --plugins xss_reflect,path_traversal --out reports/r1.json
scan-lab plugins list
```

- **边界与失败行为**：
  - `serve-target` 只允许 `--host 127.0.0.1` 或 `localhost`；其他地址拒绝启动，退出码 2；端口占用时打印原因，退出码 2；
  - `scan` 的 `--target` 必填；非本机地址被 `ensure_local_target` 拒绝，退出码 2；
  - `--plugins` 省略时使用 `config/scan.yaml` 中的 `plugins`；未知插件退出码 2；
  - `plugins list` 按名字排序列出 `NAME / SEVERITY / DESCRIPTION`。

### F8 限速与日志（`src/scan_lab/http.py`、`src/scan_lab/scanner.py`）

- **输入**：`HttpSettings.rate_limit`（默认 5 次/秒）、`--verbose`。
- **处理**：`RateLimiter` 保证两次真实 HTTP 尝试之间至少间隔 `1/rate_limit` 秒；每次尝试按 DEBUG 级别记录 `method url -> status (elapsed ms)`；`HttpClient.request_count` 统计所有真实尝试（含重试）。
- **输出**：
  - 默认 INFO 级别只显示警告与统计；`--verbose` 打开每请求 debug 行；
  - 扫描结束打印：请求数、跳过数、耗时、发现总数、各插件命中数。
- **边界与失败行为**：`skipped` = 爬虫未成功访问的后续页面数 + 插件探测时抛出的 `FetchError` / `PluginError` 次数；限速只影响发起请求的间隔，不改变并发度（始终单线程顺序执行）。

## 3. 靶场说明

### 3.1 端点

| 方法 | 路径 | 参数 | 预期行为 | 故意留下的问题类别 |
| --- | --- | --- | --- | --- |
| GET | `/` | 无 | 返回首页，含导航、搜索表单、登录表单 | 无 |
| GET | `/search` | `q` | 渲染"你搜索了：..."的结果页 | 反射型 XSS |
| GET | `/files` | `path` | 读取 `target/files/` 下文件并放入 `<pre>` | 路径穿越 |
| GET | `/profile` | `id` | 查询并渲染用户资料；不校验归属 | 越权访问（IDOR） |
| GET | `/login` | 无 | 返回登录表单 | 无 |
| POST | `/login` | `username`、`password` | 校验账号并返回欢迎页或失败页 | SQL 注入 |

本文件只列出问题类别，不提供 payload 或利用步骤。扫描器的实际验证方式见第 4 节与插件源码。

### 3.2 种子数据

`target/seed.py` 创建两张表：

| 表 | 字段 |
| --- | --- |
| `users` | `id` INTEGER 主键自增、`username` TEXT 唯一非空、`password` TEXT 非空、`email` TEXT 非空、`role` TEXT 非空 |
| `posts` | `id` INTEGER 主键自增、`author_id` INTEGER 外键指向 `users.id`、`title` TEXT 非空、`body` TEXT 非空 |

初始内容：

| id | username | password（演示用明文） | email | role |
| --- | --- | --- | --- | --- |
| 1 | alice | alice-demo-pw | alice@example.test | user |
| 2 | bob | bob-demo-pw | bob@example.test | user |
| 3 | admin | admin-demo-pw | admin@example.test | admin |

5 篇帖子：alice 2 篇、bob 2 篇、admin 1 篇。插入前会检查 `users` / `posts` 是否为空，因此重复启动不会产生重复数据。

### 3.3 文件与诱饵

- `target/files/readme.txt`、`target/files/notes.txt`：`/files` 的正常示例文件。
- 仓库根目录的 `etc/passwd`：**完全虚构**的诱饵文件，仅让扫描器在离线环境下验证
  `../../etc/passwd` 这类穿越路径；内容不含任何真实账号或凭据。靶场从
  `target/files/` 出发解析相对路径，因此可以读到它。
- `target/scan_lab.db`：运行时生成，已被 `.gitignore` 忽略。

## 4. 插件契约

### 4.1 `Plugin` 基类

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `name` | `ClassVar[str]` | 唯一插件名，也是 CLI `--plugins` 使用的标识 |
| `severity` | `ClassVar[Severity]` | `info` / `low` / `medium` / `high` |
| `confidence` | `ClassVar[Confidence]` | 固定置信度标签，默认 `medium`；当前两个插件都是 `high` |
| `description` | `ClassVar[str]` | `plugins list` 中展示的说明 |
| `__init__(client)` | 方法 | 接收本次扫描共享的 `HttpClient` |
| `match(page)` | 抽象方法 | 只做轻量判断，不应发请求；返回 `bool` |
| `run(page)` | 抽象方法 | 执行探测，返回 `list[Finding]`；允许抛出 `FetchError` / `PluginError` |
| `make_finding(...)` | 辅助方法 | 按当前插件的 name/severity/confidence 组装 `Finding` |

### 4.2 `Finding` 字段

| 字段 | 含义 |
| --- | --- |
| `plugin` | 产出该 finding 的插件名 |
| `severity` | `info` / `low` / `medium` / `high` |
| `url` | 实际发起探测的完整 URL（含注入后的 payload） |
| `parameter` | 被注入的参数名 |
| `payload` | 注入的原始 payload |
| `evidence` | 请求摘要 + 响应片段；片段优先截取命中 marker 附近上下文，最多 600 字符 |
| `repro_curl` | 可直接执行的 cURL 命令（`curl -sS -i '<url>'`） |
| `confidence` | 固定置信度标签；**不是**打分模型的结果 |

### 4.3 `match` 与 `run` 的调用时机

1. 爬虫产出全部 `Page` 后，扫描器按"插件外层、页面内层"遍历；
2. 先调用 `plugin.match(page)`，返回 False 直接跳过，不产生任何请求；
3. 返回 True 才调用 `plugin.run(page)`；
4. `run` 返回的 finding 先进入原始列表，扫描结束后统一去重；
5. `match` 或 `run` 抛出的 `FetchError` / `PluginError` 只增加 `skipped`，不影响其他页面和其他插件。

### 4.4 注册表的发现机制

- 插件模块在导入时执行 `@register_plugin`，把类写入 `plugin._REGISTRY`；
- `available_plugins()` 第一次调用时通过 `importlib.import_module("scan_lab.plugins")` 导入内置插件包；
- `scan_lab/plugins/__init__.py` 显式 `from . import path_traversal, xss_reflect`，确保两个模块被导入；
- `get_plugin(name, client)` 从注册表取出类并传入本次扫描的 `HttpClient` 完成实例化。

### 4.5 怎么写一个新插件

以现有两个插件为例：

1. 在 `src/scan_lab/plugins/` 新建模块，例如 `my_check.py`；
2. 从 `..crawl` 引入 `Page`（及需要的 URL 工具），从 `..plugin` 引入 `Plugin`、`Finding`、`register_plugin`；
3. 继承 `Plugin`，声明 `name` / `severity` / `confidence` / `description`；
4. 实现 `match(page)`：判断页面是否有值得探测的参数或表单；
5. 实现 `run(page)`：用 `self._client` 发请求，命中时调用 `self.make_finding(...)`，未命中返回空列表；
6. 在 `plugins/__init__.py` 中导入该模块，使其被注册；
7. 测试中通过 `get_plugin("my_check", client)` 获取实例，或直接在 CLI 中 `--plugins my_check`。

参考：

- `xss_reflect` 展示了"为每个 GET 参数注入唯一标记并检查响应"；
- `path_traversal` 展示了"只对文件读取参数注入、按 payload 列表依次尝试、命中即停"。

## 5. 关键流程：一次扫描的完整路径

以 `scan-lab scan --target http://127.0.0.1:5001 --plugins xss_reflect,path_traversal --out reports/r1.json` 为例：

1. **参数解析**（`cli.py`）：Typer 解析 `--target` / `--plugins` / `--out` / `--config` / 覆盖项，初始化日志级别。
2. **加载配置**（`config.py`）：未指定 `--config` 时读取 `config/scan.yaml`；文件不存在则用默认模型；YAML 或字段非法抛 `ConfigError`。
3. **合并覆盖**（`config.py`）：`--timeout` / `--rate-limit` / `--max-depth` / `--max-urls` 覆盖对应字段，仍经过 pydantic 校验。
4. **目标校验**（`config.py`）：`ensure_local_target` 只接受 `127.0.0.1` / `localhost` / `::1`，并去掉末尾斜杠。
5. **插件名校验**（`scanner.py`）：`available_plugins()` 取出注册表；未知名字在发请求前抛 `PluginError`。
6. **建立会话**（`http.py`）：按本次扫描配置创建 `HttpClient`；所有插件共享该会话。
7. **同源爬取**（`crawl.py`）：访问起点，BFS 展开链接，产出 `Page` 列表与 `skipped` 列表；起点失败直接抛 `FetchError`。
8. **插件匹配与探测**（`plugin.py` + `plugins/`）：对每个插件、每个页面先 `match` 后 `run`；`run` 内部通过 `set_query_param` 构造注入 URL，并发起 GET。
9. **证据组装**（`evidence.py`）：命中时截取 marker 附近响应片段，拼装"请求行 + 响应片段"，生成 cURL 命令，写入 `Finding`。
10. **去重**（`report.py`）：按 `(plugin, url, parameter)` 去重，保留首次命中。
11. **统计与报告**（`scanner.py` / `report.py`）：汇总请求数、跳过数、耗时、各插件命中数，构造 `Report`。
12. **落盘与摘要**（`report.py` / `cli.py`）：`write_report` 写 JSON（默认 `reports/scan-{timestamp}.json`），`print_summary` 打印终端摘要，最后输出报告路径。

异常出口：`ConfigError` / `PluginError` / `FetchError` / `ParseError` → 退出码 2；
`OSError`（报告写入）→ 退出码 1；其余正常结束 → 退出码 0。

## 6. 配置与报告格式

### 6.1 `config/scan.yaml`

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `http.timeout` | `5.0` | 单次请求超时（秒），范围 0–60 |
| `http.retries` | `2` | 失败后的重试次数（不含首次），范围 0–5 |
| `http.rate_limit` | `5.0` | 每秒最多请求数，范围 0–100 |
| `http.user_agent` | `scan-lab/0.1 (local-lab; authorized use only)` | 请求 UA |
| `crawl.max_depth` | `2` | BFS 最大深度，起点为 0，范围 0–5 |
| `crawl.max_urls` | `50` | 单次扫描最多访问页面数，范围 1–500 |
| `crawl.skip_keywords` | `["logout", "delete", "signout"]` | 路径命中即跳过 |
| `plugins` | `["xss_reflect", "path_traversal"]` | `--plugins` 省略时使用 |

CLI 覆盖项：`--timeout`、`--rate-limit`、`--max-depth`、`--max-urls`。
`--config` 指向不存在的文件会直接报错，不会静默回退到默认配置。

### 6.2 报告 JSON

顶层固定三个键：

| 键 | 含义 |
| --- | --- |
| `scan.target` | 规范化后的目标地址 |
| `scan.started_at` / `scan.finished_at` | UTC ISO 8601 时间 |
| `scan.config` | 本次扫描实际使用的完整配置（http / crawl / plugins） |
| `findings` | `Finding` 数组，字段见 4.2 |
| `stats.requests` | 真实 HTTP 尝试次数（含重试） |
| `stats.skipped` | 跳过计数（爬取失败页面 + 插件探测失败次数） |
| `stats.duration_ms` | 扫描总耗时（毫秒） |
| `stats.findings_total` | 去重后的 finding 数 |
| `stats.by_plugin` | 每个被请求插件的命中数（未命中为 0） |

## 7. 已知限制与测试说明

### 7.1 明确不实现（当前行为）

1. **SQL 注入检测**：靶场 `/login` 存在注入点，但扫描器没有错误型、布尔盲注或时间盲注检测插件，不会报告该问题。
2. **SSRF 检测与 OOB 回连**：没有外连监听服务，也没有回连判定逻辑。
3. **认证会话管理、多角色爬取、IDOR 检测**：爬虫不登录、不保存 Cookie 角色；靶场 `/profile` 的越权问题不会被检测。
4. **误报抑制与置信度打分模型**：`confidence` 是插件声明的固定标签（当前均为 `high`），没有基于多信号加权的评分。
5. **SARIF / HTML 报告**：只输出 JSON 文件与终端文本摘要，不生成其他格式。
6. **并发扫描、断点续扫、扫描队列**：单进程、单线程顺序扫描；没有任务队列与状态恢复。
7. **WAF 绕过与编码变形库**：路径穿越只尝试 4 个固定 payload，没有变形生成器或 WAF 指纹适配。

另外，爬虫会提取表单字段，但插件目前只探测 GET 查询参数，不提交 POST 表单；这是当前实现边界，不是上述七项之外的承诺。
